# Sources and versions

The original materials in this follow-up use the GPL-3.0-only license. See [LICENSE](LICENSE).

The jMCM comparison uses Rémi Garcia’s benchmarks and solver measurements at revision `d4a966a8f3ea4763ae50041ec8e03ea5369aad02`. This repository includes the normalized targets, the published solver results (`data/jmcm-results_all.csv`), and the [MIT notice](data/jMCM-LICENSE). The original tap sequences are available upstream. [jMCM deposit](https://github.com/remi-garcia/jMCM/tree/d4a966a8f3ea4763ae50041ec8e03ea5369aad02/benchmarks) · [Filter provenance](https://www.firsuite.net/FIR/FromPublication)

- Arm CMSIS-DSP supplies the Q15 table in `data/arm_common_tables.c`. We keep the source file, including its copyright header, and its Apache-2.0 license in `data/CMSIS-DSP-LICENSE`. The revision is `9f64ba31591e527c505951943b4b95b0eb2f834b`. [Arm source](https://github.com/ARM-software/CMSIS-DSP/blob/9f64ba31591e527c505951943b4b95b0eb2f834b/Source/CommonTables/arm_common_tables.c)
- The CP benchmark names and normalized targets come from `test/benchmarks.csv` at revision `e09fdaa0b11461b861b3911479f11934ebc11cc5`. The upstream project uses [GPLv3](data/CP-LICENSE). To compare both the CP and jMCM target lists with the original files, run `python3 -B src/benchmark_sources.py` in this folder. This optional check downloads two revision-pinned CSVs, verifies their SHA-256 digests and compares every normalized row. For an offline run, put the originals in one directory as `cp-benchmarks.csv` and `jmcm-benchmarks.csv`, then pass `--from-dir DIR`. [CP code](https://gitlab.inria.fr/emeraude/mcm-cp) · [CP paper](https://doi.org/10.4230/LIPIcs.CP.2026.11)
- The tables named `prior` carry the integer circuits obtained in the preceding width-bounds work. The follow-up replays every circuit and recomputes the lower bounds. `McmAudit.lean` and `R06Graph.lean` are reused from that GPL-3.0-only project.
- `data/cp-bounded-baseline.json` records the original-solver arm of that project's earlier two-second-per-instance experiment, with upstream CP revision `e09fdaa0b11461b861b3911479f11934ebc11cc5` and Choco 6.0.1. It contains the names, normalized vectors, solver status and reported optima for the 83 official rows. `src/compare_cp.py` compares those answers with the new unrestricted ledger. [Upstream CP](https://gitlab.inria.fr/emeraude/mcm-cp)
- Hcub results are numerical outputs of the SPIRAL multiplier-block generator. The archived 2009 source used for these trials has SHA-256 `24b3fd41181f2e5443f0324a4138096dfce91fa2514b0f96b25b5a1da6c33bc2`. The package includes the 32 seeded circuit outputs and a runner for an external installation. [SPIRAL generator](https://spiral.net/hardware/multless.html) · [Voronenko and Püschel, 2007](https://doi.org/10.1145/1240233.1240234)
- Hardware mapping used the Berkeley ABC binary supplied with Yosys (recorded binary SHA-256 `4df0ad5b70439cf0e5d279f906ab6012e78063cb59ba6960c84df16beca9f2b0`) and the Nangate45 typical Liberty file (SHA-256 `8d540a4d4cf6d09d27c87ad067857a9c0c2eeb023ab7a56e058cd3113db4e9b1`). Both can be supplied to the optional mapping command. [ABC](https://github.com/berkeley-abc/abc) · [Nangate45 library](https://github.com/The-OpenROAD-Project/OpenROAD-flow-scripts/blob/master/flow/platforms/nangate45/lib/NangateOpenCellLibrary_typical.lib)
- The proof sources import Lean 4.19.0 core and Std. The optional second checker is lean4lean revision `c0273e3c2de46a7de695fca618376a5b9aa84489`. Verilog simulation used Icarus Verilog 13.0. [Lean release](https://github.com/leanprover/lean4/releases/tag/v4.19.0) · [lean4lean](https://github.com/digama0/lean4lean) · [Icarus Verilog](https://github.com/steveicarus/iverilog)
